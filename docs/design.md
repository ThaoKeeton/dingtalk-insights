# 长期监控与按需整理 MVP

用户目标：独立 Windows 图形应用，长期检查选定钉钉会话，用可配置低价模型发现可能的沟通难点；用户提出整理事项后，软件搜集相关消息并整理。结果在界面查看，也可手动发送 Webhook。用户已在自己的本机验证 DWS 权限可行；开发环境不复用或导入其登录。

## 实现选择

采用 WinUI 3 / .NET 8 Windows 原生界面（与 UPCAM 的 NavigationView、Mica、设置卡片体验一致），加不依赖 Windows 的 .NET 核心。直接调用已安装的官方 DWS 可执行文件，不搬运 DWS 凭据，不访问钉钉客户端数据库。与 Python worker 相比，单一 .NET 运行时减少进程协议与双运行时打包；Web/Electron 会偏离用户要求的原生体验。

## 两条主要流程

1. 持续检查：明确身份、单一会话、开始时间、间隔、保留期及是否允许模型上传 → 预览并授权本次运行 → 每次读取最多一小时的增量窗口 → 加密保存消息与覆盖区间 → 完整批次推进断点，重叠两分钟去重 → 尚未尝试的消息最多 40 条一批 → 请求前持久保存费用预留与尝试记录 → 模型给出带证据的待核实候选 → 界面查看。缺页、授权失败、保存失败时暂停；明确可重试的 DWS 读取故障有界退避，预算耗尽保留候选并继续安全采集，模型延后下个 UTC 日；用户恢复后从断点追赶。不会自行发送消息。
2. 按需整理：用户输入事项 → 核对可编辑关键词、身份、会话和时间 → 搜索本机已采集索引，或经确认通过 DWS 检索 → 查看最多 40 条实际候选原文 → 确认向 OpenAI 上传这一批正文与整理事项 → 验证结果结构和原文引用 → 查看、导出，或预览完整正文和目标群后确认发送一次。关键词检索不代表穷尽所有同义表达；范围外历史和未读附件始终提示限制。

默认每次启动为模拟模式；v0.2 可另行明确批准精确配置在下次手动启动时恢复。WinUI 用户会话托盘宿主、核心监督器和恢复权限详见 [后台监控设计](background-monitoring.md)。关闭到托盘也是明确选择；通知区域失效恢复可见窗口。停止撤销恢复，退出遵守单独批准的策略。休眠、注销和退出不实时采集；没有开机自启动安装或 Windows 服务。

## 断点、成本与持久数据

本机消息索引按身份、会话和消息 ID 去重，修订内容更新记录；完整覆盖区间合并时不跨越缺口。断点、消息修订、模型尝试记录、费用预留和最近结果使用一个原子替换的 DPAPI 加密状态文件，单实例文件锁防止并发覆盖。默认保留 30 天，最多 50000 条消息、32 MiB 加密状态和 100 份结果，超限暂停。

默认模型 `gpt-6-luna`，输入/输出参考单价为 USD 0.10/0.50 每百万 tokens，来源核对日期 2026-11-06；模型和单价均可配置。请求使用文本与严格 schema，最多 48 KiB 请求、2000 输出 tokens；按 UTF-8 字节数加 framing 余量保守预留费用。每日默认预留上限 USD 0.50、最多 200 次请求，按 UTC 日计。失败、超时和进程崩溃不返还预留；监控不会自动重试同一修订的未知模型结果。该限制仅覆盖本应用依据配置单价估算的用量，不是平台账单或账户全局消费保证。

## 安全和可信边界

- 聊天正文与模型输出都不是操作指令。模型没有工具；消息文本仅进入 user 数据载荷，固定开发者指令优先。界面只用纯文本控件，不执行 HTML、命令、链接或远程图片。
- 每个问题必须有至少一条可核验的消息 ID 和逐字原文片段；不存在的 ID、非原文引用、无证据的状态、结构错误和不完整的模型响应均拒绝。
- 模型的 resolved 一律变为 pending_verification；只有用户针对当前问题与证据明确确认，才会显示已解决。人工确认只修改当前预览及当前导出/发送，不写回保存历史；界面明确提示其临时性。重做或重开历史需重新核实。
- DWS 的完整性 ledger、分页失败和截断保留。未知或矛盾字段按不完整处理；即使分页结束，也不承诺附件、撤回、服务端索引和历史范围全部可见。
- 只读取当前用户明确选择的会话，不自动扩大到所有会话。固定命令列表、ArgumentList、无 shell；DWS 非零状态不能被当作完整成功。
- OpenAI 端点固定为官方 HTTPS，Responses API、store=false、无工具、严格 JSON schema；客户端关闭重定向，限制请求/响应大小和超时，无自动重试。
- Webhook 仅允许 https://oapi.dingtalk.com/robot/send，禁止重定向和 @所有人；支持 HMAC 加签。超时视为结果不确定，不能自动重发。
- 本机凭据由 Windows DPAPI CurrentUser 加密保存到 LocalAppData，窗口不回显已保存密钥；配置不含密钥。开发环境密钥的创建和仓库外保存另行确认，不依赖该步骤执行模拟测试。
- 一次性读取、按需 OpenAI 上传与 Webhook 发送需要对应确认。持续检查的授权绑定明确身份、单一会话、起始时间、模型、预算和当前运行期；另行批准的重启恢复绑定来源摘要、凭据版本及全部监控配置；修改配置需先停止并重新授权。Webhook 始终手动确认，不随监控授权自动发送。
- 不把原文、密钥、服务响应体或带查询参数的 Webhook 写入日志。原文只在内存与本机 DPAPI 加密索引中保存，导出需用户显式选择。
- 模型结论只作为待核实候选，不用于人员能力、人格、动机或绩效评价。逐字引用校验只能验证引用来自输入，不能证明模型理解正确，仍需要人工核实。

## 首版范围

范围：模拟完整链路、DWS 会话发现与单会话按时间增量读取、断点恢复和去重、本机加密索引及关键词搜索、按需 DWS 搜索、可配置低价模型和费用上限、原文预览、证据校验、人工确认、Markdown 导出与手动 Webhook、主题选择、Windows 自包含 ZIP 与原生启动测试。

后续：实时事件订阅、长期问题合并与跨批次语义关联、自动更新、开机自启动、Windows 服务、多账户管理、附件内容提取。两分钟重叠不能保证捕获更早消息的编辑和撤回；首版不冒充完整实时审计工具。

首版为 Windows x64、Windows 10 19041+；界面为中文。DWS 由用户独立安装和授权，不捆绑静默安装。

## 2026-11-06 修复决策

- 监控起点与请求范围分开验证。加密状态保存最近授权的身份、会话及原始起点；启动仍为模拟、不自动采集。切换 DWS 恢复该配置，开始确认显示断点及改晚起点将放弃的未覆盖缺口。起点可超过 31 天，实际读取为一小时加最多两分钟重叠；不静默把多日停机变成最近 24 小时。
- 保留期以来源创建时间为准，在加载、保存及搜索/使用前清理。DWS 单次读取/搜索范围须完全落在保留期内；本机搜索与保留索引相交，过期候选拒绝再用。监控起点早于保留期时不跳过缺口，需明确扩大保留天数或改晚起点并确认。编辑保留字段本身不执行删除，保存设置或确认开始真实监控后生效。
- 保存报告记录该批最早来源时间，按生成时间和来源时间共同到期；重启立即装载历史，可直接查看/导出。历史选择先完成保留期校验与保存，失败时捕获错误、清空待载入预览并取消选择；过期预览在保存前失效，清理后同步刷新选择列表，不因这次手动失败取消监控。旧版本无法确定来源年龄的历史报告清理。显式扩展保留期允许再次读取新授权范围，不能恢复已删除正文。
- 每份尝试记录关联来源创建时间，保留所有已尝试修订直至来源到期。旧版本无法反推来源的哈希保守保留迁移后最长支持的 365 天保留周期；已被旧版本删除的保护无法还原。清空索引仍保留预算、请求数和 token 统计。
- 最近 100 份采集回执持久保存范围、完整性、限制与原始 ledger，均在同一 DPAPI 文件中。每份 ledger 最多 32 KiB；超出则省略其原始值并保存明确标记，不影响本批是否完整的原有判定。界面只显示数量与完整性统计，不展示原始服务错误。元数据不能补足附件、撤回或源端不可见历史。
- DWS 仅当请求范围元数据、升序终止原因与所有完整性标志一致时推进覆盖。缺失/未知终止与范围或畸形补充标志都不推进；空消息结果同样校验。已核对官方 v1.0.67 的 source_complete 与 range_end，range_start 属降序，不符合本应用固定升序请求。
- OpenAI/Webhook 使用统一取消期限覆盖发送、响应头及正文读取，最多 90 秒且服从调用方更短期限，不自动重试。手动失败不取消另一个已授权监控，监控轮次失败仍暂停。
- 模拟范围和消息使用捕获参考时间之前的三小时，并在窗口生命周期固定；完整范围也落在最短一天保留期内，不改变真实数据保留规则。2034 年 10:00 UTC+8 及全天参考测试覆盖范围校验、入库和本机搜索。

本次核心合成验证不能替代 Windows 原生编译、控件禁用与 DPAPI、打包及重启 smoke；它们通过 Windows CI 执行。没有访问真实 DWS、OpenAI 或 Webhook，也不宣称真实服务验收。
