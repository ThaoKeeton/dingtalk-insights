# DingTalk Insights

独立 Windows 原生应用：持续检查选定钉钉会话，发现可能的沟通难点；也可以输入整理事项，搜索相关消息后形成带来源的待核实摘要。界面查看、导出 Markdown，按需发送到已确认的钉钉 Webhook。

v0.2.0 使用 WinUI 3 与 .NET 8。默认模拟模式，不自动登录、采集、上传或发送。适用于 Windows 10 19041+ / Windows 11 x64。

## 两种用法

- **持续检查**：在“连接与设置”指定官方 DWS、明确身份和单一会话，在“持续检查”设置开始时间、间隔及是否允许模型上传，确认后运行。完整批次才推进断点；原始起点、身份及会话跨重启保存，默认切换回 DWS 后重新确认才运行；可另行明确批准同一配置在下次手动启动应用时恢复，不把停机缺口改成最近 24 小时。改晚起点会在开始确认中明示放弃的缺口；每次真实读取最多一小时加两分钟重叠。重新开始从断点追赶，保留两分钟重叠并去重。模型每次处理最多 40 条新增或修订消息，结论都是待核实候选。
- **按需搜集整理**：输入整理事项，核对关键词、会话与时间；选择搜索本机索引，或确认一次 DWS 搜索。先查看实际候选原文，再确认是否交给模型。搜索可能遗漏同义表述和范围外内容，不表示全面覆盖。

v0.2 是已登录用户会话内的托盘应用。开始时可分别选择并确认“关闭窗口留在通知区域”和“下次手动打开应用恢复此监控”，默认均关闭。通知区域提供打开、停止和退出；图标不可用时窗口保持/恢复可见。停止撤销重启恢复权限；退出保留另行批准的恢复策略。第二次启动只打开已有窗口，不启动第二个采集器。

应用需要用户已登录并手动打开；休眠、注销、退出期间不会实时采集。恢复使用原始起点和一小时有界窗口追赶，不跳过过期缺口。没有 Windows 服务、开机自启动安装、自动更新、附件正文读取或自动发送。

## 先试模拟模式

1. 打开应用，保持默认模拟来源，点击“检查一次并预览原文”。
2. 在“按需搜集整理”核对模拟消息，再点击“整理当前候选”。
3. 在“结果与发送”查看问题、待确认事项与消息 ID、时间、发送人、原文引用。
4. 模拟发送只显示预览，不会请求真实 Webhook。无需任何真实密钥或聊天记录。

## 连接真实服务

用户已在本机验证 DWS 可行。新电脑仍需独立安装[官方 DWS](https://github.com/DingTalk-Real-AI/dingtalk-workspace-cli)，在自己的电脑完成登录并核对企业授权。详情及核对过的固定命令见 [DWS 接入边界](docs/DWS.md)。本应用不复制 DWS 登录，也不从钉钉客户端数据库提取数据。

先用一个已获授权会话和短时间范围核对原始消息，再按公司政策决定是否允许上传 OpenAI。应用使用专用 OpenAI API 密钥；通过安全流程创建后，在本机设置页录入，确认后由 Windows DPAPI 加密保存。已保存凭据不会回显，不要将密钥、Webhook 或真实聊天提交到仓库。

默认低价模型是 `gpt-6-luna`，可修改模型和单价。默认每日费用预留上限 USD 0.50、最多 200 次请求、每次最多 2000 输出 tokens。输入/输出参考价为 USD 0.10/0.50 每百万 tokens，核对日期 2026-11-06，见 [OpenAI 官方模型价目](https://developers.openai.com/api/docs/models/gpt-6-luna)。费用在请求前保守预留，失败或崩溃不返还，避免自动重复扣费；该限制不是 OpenAI 平台账户的全局消费上限，单价需按实际模型核对。

Webhook 每次都预览完整正文和明确的接收群，再确认发送一次。本维护分支用同目录 DPAPI `send-attempts.dpapi` 保存目标与正文的摘要及发送尝试；中断、重启、清理索引不清除此记录。同一正文与目标默认不重发，人工再次确认也可能重复送达；不承诺端到端恰好一次。支持官方自定义机器人 HMAC 加签，禁止全员提醒，禁止重定向。超时标记为结果不确定，不会自动重发。

## 本机数据与结果可信度

消息、断点、修订去重、模型尝试记录、费用预留及最近结果加密保存到 `%LOCALAPPDATA%\DingTalkInsights\state.dpapi`；凭据保存到同目录 `credentials.dpapi`。普通设置不含密钥。恢复权限和有界健康记录也保存在加密状态内，旧版缺字段默认没有恢复权限。恢复授权绑定稳定身份、单一会话、原始起点、DWS 路径和可执行文件摘要、是否上传、模型/单价/输出/费用/请求上限、间隔、保留期与本应用凭据版本；变化或就绪状态不明会阻止恢复。DWS 只读状态没有可靠的同身份登录代际字段，不能据此检测同一身份重新登录；授权故障仍会暂停。默认保留 30 天，最多 50000 条消息、32 MiB 状态及 100 份结果。存储超限、保存失败、缺页、未知故障或权限失败时暂停。只有 DWS 明确结构化标记可重试的读取故障才按配置间隔指数退避，最多 5 次，通常最多 15 分钟（较长配置间隔仍遵守）。预算/请求限额到达时保留未尝试候选并继续安全采集，模型等下个 UTC 日重新核对限额。未知模型结果保留尝试与费用预留并暂停自动 AI，本机采集继续；未整理不代表没有问题。

保留期在启动、每次保存和搜索/使用前执行。编辑保留天数在保存设置或确认开始真实监控后生效，缩短会清理到期内容。DWS 单次读取/搜索必须在保留期内；本机搜索只返回仍保留的原文。过期候选不能再次上传，含引用的报告按最早来源时间到期。旧版本缺少来源年龄的报告会安全清理，无法恢复已经清理的内容。监控起点可早于 31 天，但下一小时窗口必须在所选保留期内；更早缺口需明确增加保留天数或在开始确认中放弃。清空索引保留当日预算与用量。

重启后最近报告立即显示，可直接选择并导出，不必重新请求模型。最近最多 100 份采集回执加密保存，保留完整性限制；单份原始元数据超过 32 KiB 时省略原文并保留省略标记，界面仅显示安全统计。失败的同一来源修订记录一直保留到来源到期，A→B→A 不会自动重试未知 A。HTTP 的 90 秒上限覆盖响应头和正文；Webhook 不确定结果仍不自动重发。手动流程校验或历史结果读取失败仅影响该次操作；历史保存失败不展示待载入结果，也不停止无关监控，监控自身失败仍暂停该监控。

消息正文和模型输出都当作不可信数据；正文中的命令不执行，模型没有工具。每个问题必须引用实际消息 ID 和逐字原文。模型提出“已解决”也先降为待验证；只有人工回原会话核实后，才能在当前预览中确认解决。人工标记仅影响当前预览及其导出/发送，未写回已保存历史；重新打开历史仍需核实。引用匹配不能证明模型理解正确，候选结论仍需核实；不进行人员能力、人格、动机或绩效评价。

本地保留期、可见历史、分页、索引延迟、附件、撤回和较早编辑会限制结论，完整分页也不代表完整审计。完整架构与限制见 [设计说明](docs/design.md)。

## 开发与验证

核心没有第三方运行时依赖，Linux、macOS、Windows 均可运行合成测试：

```sh
dotnet run --project tests/DingTalkInsights.Tests -c Release
```

Windows 构建：

```powershell
dotnet publish src/DingTalkInsights.Desktop/DingTalkInsights.Desktop.csproj -c Release -r win-x64 --self-contained true -p:Platform=x64 -o dist/app
```

GitHub Actions 的 [Windows native MVP](.github/workflows/windows.yml) 运行核心测试、自包含构建、真实 WinUI 控件与 DPAPI 合成检查、独立进程重启后的历史/保留期/监控起点恢复、合成后台恢复与停止撤权、第二实例激活、通知区域隐藏/打开及失败保持可见，并从解压后的 ZIP 重复检查。模拟范围为注入参考时钟之前的三小时，兼容最短一天保留期；单次应用运行保持稳定，不依赖固定发行日期。无 Explorer 的 runner 只验证通知区域失败回退，JSON 单独报告实际 shell 路径是否验证。通过后在 Actions 产物下载 `DingTalkInsights-Windows-x64`，完整解压内部应用 ZIP 后运行 `DingTalkInsights.exe`，保留所有 DLL 与 PRI。产物未进行 Authenticode 签名。

代码和测试均使用合成消息及合成凭据；持续监控、真实 DWS 可见范围、真实模型用量和 Webhook 接收仍需用户在授权本机验收。第三方许可说明见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

后台策略、实现决策与测试清单见 [v0.2 背景监控设计](docs/background-monitoring.md)。
