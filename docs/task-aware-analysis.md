# 按事项整理与重复处理保护

以前插件用来源修订的全局尝试记录过滤所有按需候选：监控或事项A处理过的消息，即使用户想查不同事项B也会被隐藏。独立版按需入口又没有同等检查。本版独立应用0.2.2和插件0.3.4使用共同规则。

身份由明确的用户身份、会话、消息ID及完整消息修订确定；事项文本按Unicode规范分解、固定Unicode 15.1 C/F完整大小写折叠、NFC与空白归一化后哈希。同事项同来源修订一旦尝试，包含超时、取消、保存失败或未知结果，都不会自动再发；预览可排除已尝试来源，只处理剩余候选。时间窗口的扩大或缩小、换模型、Unicode 15.1支持的大小写及空白不能绕过此保护。15.1之后新增字符的大小写变体或不同措辞可能视作新事项；先前来源仍必须单独确认。新修订是新来源，旧修订在A→B→A时仍保留原尝试直至到期。

不同事项可复用以前尝试过的来源。无论旧尝试成功还是未知，先单独确认这是不同事项并接受可能再次处理、再次计费；随后核对完整候选、模型请求与费用预留。取消任一步都不派发。每个明确批准的新事项确实是一次新请求，正常计入UTC预算；系统无法判断不同措辞是否语义等价，不应靠改字重试未知请求。

## 已有用户数据与回退

旧版只保存来源修订的全局尝试，没有事项或结果状态，不能可靠判断先前是哪个事项或是否完成。旧记录仍阻止监控自动重试；按需复用时显示风险并要求单独确认，由用户核对是否确实是不同事项。旧版遗失的未知结果无法从报告文本反推。如果旧版重写已经丢弃新增字段、备份又同时遗漏了新侧账，系统也无法认出那个旧事项的原始文本；这种不可恢复的歧义仍不会自动派发，用户误把同一事项确认成不同事项可能再次计费。

新版在 `state.dpapi` 及同一账本锁保护的 `analysis-attempts.dpapi` 保存来源尝试哈希、事项哈希和来源时间，侧账不保存任务或消息原文；数据用本地DPAPI加密。侧账与规范状态采用单调合并，并在模型派发前先写侧账，再持久保存全局尝试及预算。若侧账成功但规范保存失败，不会调用模型；该事项仍保守地视为已尝试，需要核对，避免崩溃后重试。

旧独立版重写状态时不认识新增字段，但不会删除侧账；新版重新接手时合并侧账，同事项保护仍在。旧二进制自身没有按事项保护，回退期间不要用旧版再次人工整理同一来源。旧版手动发送也不识别现有发送侧账，回退期间不要发送。升级/回退先停用或断开并等待锁释放，保留整个数据目录。

侧账损坏、缺失或保存失败时不派发模型、不自动覆盖坏文件；保留期内原始历史可只读查看/导出。若账本原本没有恢复授权，插件可只读连接历史和明确清理索引；存在旧恢复授权时必须先持久撤销，存储故障导致无法撤权时拒绝连接。修复文件或明确清理本机索引可恢复；清理索引会删除来源、断点、模型尝试和结果，未知结果可能已经计费，清理后同事项可能重新处理和计费；当日预算及发送尝试保留。每源最多128个事项、最多100000个来源，侧账32MiB，规范状态仍按既有30MiB上限保护；超限安全拒绝而不静默删除未到期尝试。
