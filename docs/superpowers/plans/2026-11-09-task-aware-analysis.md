# 按事项隔离整理尝试 Implementation Plan

> 执行方式：superpowers:executing-plans；用户已授权自主选型和实施，无需等待常规设计确认。最终提交前做独立审查。

**目标：** 同一来源的不同人工事项可经单独风险确认整理，同时保留同事项未知结果、费用、监控和发送保护。
**设计：** `docs/superpowers/specs/2026-11-09-task-aware-analysis-design.md`。Core按来源修订和归一化事项去重；Runtime用同账本锁下的加密侧账保守合并；独立版和插件明确显示二次处理风险及精确请求。

## 测试与实现

- [ ] 写合成测试并复现来源经A处理后B被错误拦截，核对当前两种应用入口。测试同事项/未知结果、不同事项、旧版歧义及预算边界。
- [ ] Core增加有界任务尝试、统一选择与最后派发检查；监控保留全局来源去重。预留及尝试必须在任何模型调用前保存。
- [ ] BusinessStore增加单独加密侧账与单调合并，验证崩溃、旧二进制状态重写、存储损坏、保留期、清理、同账本交接和不确定发送保留。
- [ ] 插件一次性预览和独立版原生页面显示既有尝试数，单独确认不同事项与可能再次计费，再使用绑定同一候选的常规模型请求确认。WinUI控件只在UI线程读取。
- [ ] 用合成数据覆盖生产按钮、进程重启和固定宿主包装；更新文档与补丁版本，不修改SDK/宿主固定版本。
- [ ] 独立审查、最终本地回归和公开Windows Actions；报告精确提交、包、未运行阶段及阻碍，不创建PR/合并/部署。
