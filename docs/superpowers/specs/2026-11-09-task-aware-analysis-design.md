# 按事项隔离整理尝试

基线是 `f8d198a4bbd71cce0c71c5b3e19ba4bb278bf1c8`。监控及按需整理共用来源修订全局尝试集合，因此相同来源先经监控或事项A整理后，插件的事项B没有候选；独立版按需入口反而未校验重复尝试。目标是在两条路径提供同等、可持久、明确授权的按需去重，不改监控范围或发送策略。

实现者决策：候选身份为来源的身份/会话及消息修订，事项身份为去除首尾空白、合并连续空白、Unicode规范分解、固定Unicode 15.1 C/F完整大小写折叠后NFC的文本哈希。它不做语义等价判断：改写或15.1之后新增字符的大小写变体可能被视为新事项，界面须说明。对匹配的同一事项与来源修订，任意先前尝试（包括未知、失败或中断）都拒绝重复；新增事项可选择同一来源，但必须单独确认这是不同事项且可能再次计费，再确认完整精确请求和预算。部分已尝试来源从候选中排除并提示数量。用户未确认、旧预览、过期来源或凭据撤权均不调用模型。

旧全局尝试无事项与结果信息，不能推断成功或新旧事项不同。它们继续阻止监控自动重试；用户为新事项重用旧来源时必须经过同一风险确认，旧版未知事项是否与新输入相同须由用户核对。不能伪称可推断旧结果。改变模型、Unicode 15.1支持的大小写或空白不绕过同事项保护；跨会话、原文新修订或新事项按明确身份独立。

新事项记录只存来源尝试哈希、来源时间和事项哈希，不含明文；在模型调用及预算预留持久化前先写入受同一账本独占锁保护的 `analysis-attempts.dpapi`，并与规范状态中的记录保守合并。合并仅增加记录；侧账已写而状态写失败或进程崩溃时，后续恢复视为已尝试而不自动重试。旧独立版重写state不会删除侧账，新版恢复同事项保护；旧版自身不识别新增保护，回退期间不得用旧版再次人工整理同一来源。侧账损坏、丢失或无法保存时拒绝模型调用并保留原文件；结果/保留历史可只读访问。过期来源记录同时清除，明确清空索引时清除；费用预留和发送尝试仍保留。

按需与监控均在提交模型前保存全局来源尝试、事项尝试和UTC预算。原发送账本不改。模型/企业接口均使用本地替身；Windows自动验收使用公开 Actions。固定 Workbench SDK/宿主 `27154465c08d132798c8ea7b637f137f7340a90b`，不修改平台仓库、凭据权限、PR或用户电脑。
