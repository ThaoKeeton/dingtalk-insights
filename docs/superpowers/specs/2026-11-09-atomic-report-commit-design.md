# 报告与模型状态的崩溃恢复

基线 `b6126323b84d2b68bd2dbcba15ea60c1fbf98514` 先保存旧式报告，之后界面才捕获结构化模型快照；进程在两者之间退出时，已保存报告会丢失原始模型状态。按需整理和监控共用引擎，监控回调可能被停止或取消跳过，因此提交不能依赖界面。

将经校验的报告及初始快照先写入同一账本锁保护的单条加密提交日志，再替换规范状态，最后将日志合并进现有核实账本。规范报告附加随机提交标识，用于区分旧版清理或重建后的同形报告；旧版不认识该标识但不会删除独立日志。恢复仅在规范状态仍含唯一匹配标识时自动合并，冲突或旧版丢弃标识时保留日志并只读阻断，不猜测归属。重启后恢复的快照保守标记为历史，避免旧版期间的 A→B→A 被误当当前；既有人工作出的决定和失效标记不可被日志覆盖。

报告达到 100 条时，在规范状态确认替换前保留旧状态中未过期的核实快照；确认替换后再清理被淘汰条目并合并新条目。真正到期的内容仍须在规范状态写入前清理；清理失败保留文件并拒绝声称成功。日志损坏、缺失或提交结果不确定时保留原数据，阻断新模型派发和可能覆盖的普通写入；停止或撤权只基于重新读取的规范状态保存撤权，不覆盖待恢复报告。无法持久保存时报告存储错误，恢复流程不自动启动。

模型调用前的预算和来源尝试仍先保存；快照/规范状态失败不自动重试模型或发送。进程终止恢复使用虚构数据测试；现有文件替换尚未证明断电和底层文件系统故障时的跨文件持久顺序，不作此保证。旧程序不读取独立日志，回退前应先用新版完成恢复；旧版期间不能保证即时清理日志。
