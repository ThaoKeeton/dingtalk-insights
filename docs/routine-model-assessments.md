# 常规整理与模型判断

独立版 0.2.3 和插件 0.3.5 中，持续监控经范围及预算授权后自动整理；按需整理在现有请求预览确认后生成结果。两者均可直接查看和导出结果，不要求逐项人工核实。模型输出仍须通过结构、来源 ID 及逐字引文校验；模型说 `resolved` 时显示“模型判断已解决（未人工确认）”，不自动成为人工确认。无充分解决证据的事项仍显示待验证，范围不完整时会提示限制。

人工确认和撤销仍是可选操作，分别保存，并只绑定该报告及引用的来源修订。只要模型输入中的任一来源被本机发现已修订或缺失，模型结果即持久标为历史，不代表当前状态；仅未引用输入变化不会撤销仍绑定引用证据的人工确认。引用证据变化或缺失会使人工确认失效。模型对来源的判断不证明其理解正确；未重新读取的源端编辑或撤回无法自动发现。

结果的规范旧式 Markdown 保持不变，结构化证据快照保存原始模型状态和全部输入的来源键与修订摘要，新版显示时组合成人可读结果。这些字段与人工记录同在加密的 `report-reviews.dpapi`，采用规范账本锁、原保留期及容量限制。旧版可读新版记录，旧版修改人工决定不会丢失原始模型状态，但会丢弃新增的全输入修订字段；回到新版后标为“来源状态未明”，不会当作当前结果。旧快照当初已经把模型 `resolved` 写成 `pending_verification`，无法追溯或猜测原判断。旧版纯 Markdown 历史仍原样可读。

若快照无法保存，当前结果可显示但会给出提示，来源状态保守标为未明；重开历史只能看到旧式文本，模型原始状态不保证保留，不能凭空产生人工确认。进程在旧式结果保存后、快照保存前中断也有相同限制。日预算、未知模型结果和同事项尝试的行为不变。

新报告若在同一时刻与已有报告的旧式身份完全相同，会使用相邻的时钟 tick 区分，避免状态串到另一份报告。对于已经存在的重复旧报告，无法判断人工记录或模型判断属于哪一行：保留原始快照和文本，但只显示旧式文本，不转移确认；即使后来只剩一行也不会恢复不确定的归属。报告的最早来源时间仍限制保留期。

发送仍须单独预览确认。发送前会在原 `send-attempts.dpapi` 同一次持久化中记录正文哈希和报告身份哈希，并核对已知旧式正文，防止同一报告因新旧格式不同而绕过既有尝试。旧快照、来源失效、人工确认/撤销或快照不可用时，可能存在无法枚举的旧式发送正文；即使查不到记录，也要求单独确认重复送达风险。此确认不保证端到端恰好一次。旧二进制不识别新版报告身份哈希，回退期间不要发送。

## 合成验证

```sh
dotnet run --project tests/DingTalkInsights.Tests -c Release
python scripts/test-assessment-rollback.py --report artifacts/assessment-rollback/result.json
```

后一命令以 Git 精确导出上一版 `7b03098f730d263f22a1d183b7fee7dc57c42017` 的 Core/Runtime 源码，编译独立进程，依次检查新版写入、旧版读取及人工确认/撤销、新版恢复；另检查旧版写入的新版本读取，以及旧版账本重写保留报告发送哈希。Windows 还用合成数据经真实 DPAPI 重复。旧版自身不展示新增模型判断；不访问企业接口、真实聊天或真实凭据。

插件工作流使用固定平台 SDK/宿主 `27154465c08d132798c8ea7b637f137f7340a90b`，独立版和插件均用原生 UI 及合成数据测试。真实 Windows 11、企业接口和最终平台二进制集成未验证。
