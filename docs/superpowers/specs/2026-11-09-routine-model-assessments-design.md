# 常规整理显示模型判断

基线为 `7b03098f730d263f22a1d183b7fee7dc57c42017`。真实监控在一次范围与费用授权后可自动整理；按需整理已可查看和导出结果，不需要人工核实才能继续。但当前验证器把模型 `resolved` 一律归入待验证，连模型自己的判断也不可见，界面文字还暗示必须逐条人工核实。这与用户希望直接获得常规整理结果的体验不一致。

保留两个不同维度：已有 `Issue.Status` 与 `HumanConfirmed` 只记录原先的人工确认语义；新增的模型原始 `resolved` 标志仅用于明确显示“模型判断已解决（未人工确认）”。模型输出仍须通过严格结构和原文引用校验；不将模型判断当成人工确认、跨报告决定或自动发送。`open`、`in_progress` 和 `pending_verification` 保留原含义；来源不足时不得推定解决，范围不完整仍显示限制。报告生成、展示、导出均不要求人工核实；人工确认仍为可选操作且只绑定原报告和证据。

为兼容已有加密账本，保留 `SavedReport.Markdown` 与旧 `ReportRenderer.Markdown` 的字节语义。面向用户的渲染单独展示模型判断。新证据快照在现有 `ModelJson` 的受支持状态字段中保留原始 `resolved`，并另存全部输入的来源键和修订摘要；旧程序会把它视为待验证并仍可验证旧式 Markdown。旧版修改人工记录时不丢失原始模型状态，但会丢弃新增输入修订字段，回到新版只能标为来源状态未明。任一输入变化会持久标记模型结果为历史，人工确认只在引用证据变化时失效。旧快照当初已把 `resolved` 写成 `pending_verification`，无法补推模型原始判断；旧 Markdown 仍原样可读。若可选证据快照写入失败，当前结果保守标为来源状态未明，历史回退为旧式文本且不能声称已保留模型状态或人工确认。

同一报告不同渲染的发送在原发送账本中增加报告身份哈希，与实际正文尝试在派发前同一次写入；同时识别可计算的旧正文。旧快照、人工决定及来源变化等无法枚举旧格式的情况须单独确认重复送达风险。保留同事项未知结果保护、预算预留、监控与发送权限和二次处理确认。仅用合成输入、独立账本和本地替身；固定平台 SDK/宿主不变。旧版实际源码的独立进程读写及新旧版本恢复、独立版和插件 Windows 原生交互均须验证。
