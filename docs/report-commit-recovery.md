# 报告与模型原始状态的恢复

独立版 0.2.4 和插件 0.3.6 共用同一套账本逻辑。过去报告先保存，界面稍后保存结构化快照；两步之间进程退出会保留报告文字，但丢失模型原始 `resolved` 状态。新版先在同一账本锁下写入经验证、DPAPI 加密的 `report-commit.dpapi`，再保存规范报告并将快照合并到 `report-reviews.dpapi`；成功后删除恢复日志。模型判断不变成人工确认。

重新打开目录时，只有规范报告的提交标识与日志唯一匹配才恢复。恢复的证据保守标记为历史，已有人工记录和失效标记不会被覆盖。报告已不存在或真正过期时清理日志。若文件损坏、缺少必须的快照，或旧程序重写规范报告时丢失标识，新版保留日志并阻止后续模型工作和普通写入，提供保留期内的只读原文；检查存储并用新版重启。停止和撤销恢复授权基于重新读取的规范状态执行，不会用旧内存覆盖结果。若存储本身不可写，会明确报错。

到达最近 100 份报告上限时，旧报告的未过期核实保留到规范报告替换成功后；真正过期的证据仍按保留期清理。明确清理索引时先持久保存撤权和保留期参考时间，再写入加密的 `index-clear.dpapi` 意图、保存规范清理结果、删除相关侧账。中断后仅在规范状态和侧账与清理前或清理后状态相符时继续；若旧版介入并产生新尝试或更改，保留文件并阻断，不删除新工作。清理未完成会报错，费用预留与发送尝试保留。模型调用前保留原有尝试与费用预留；恢复不会自动重新调用模型或发送消息。

交接、备份、升级和回滚请保留整个数据目录，包括出现时的 `report-commit.dpapi` 和 `index-clear.dpapi`。先停止并释放同一账本锁，用新版完成恢复后再考虑回退。旧二进制不理解恢复日志、清理意图或提交标识，不能保证回退期间处理日志、去重或即时清除过期日志；若已经由旧版改写且身份无法证明，新版不会猜测合并。回退期间不要让旧版采集、改写来源或发送：旧版可能无法发现未引用来源 A→B→A，恢复新版后也不能证明该结果仍为当前。旧 Markdown 历史仍可阅读，但旧历史丢失的模型判断无法逆向推断。

可复现回归：`dotnet run --project tests/DingTalkInsights.Tests -c Release`。测试使用虚构消息、本地加密替身和独立子进程，在日志落盘后、规范状态替换后、快照合并后终止；也覆盖失败写入、保留期、100 份历史上限的失败替换与成功淘汰、仍保留的人工记录、冲突与孤儿日志、失效标记、撤权、取消、未知结果和旧格式改写。Windows 工作流还验证真实 WinUI 和 DPAPI 的隔离合成路径。这些测试覆盖进程中断，现有文件系统写入顺序未证明断电或底层磁盘故障下的跨文件原子性。真实企业接口与真实聊天未参与验证。Linux 或 Windows CI 不能代替 Windows 11 24H2 人工验收。
